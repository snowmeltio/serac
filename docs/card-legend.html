What every mark on a card means

A Serac session card packs a lot into three short rows. This is the decoder: every pill, chip, badge, and wash, rendered at its real size in its real colours, with what it's telling you and what you'd do about it.

Status the pill, and the stripe down the left edge

Status is carried twice over: as a word in the pill and as a colour on the card's left edge, so you can triage a column of cards by stripe alone. The elapsed time is always time in this state, which is the actual triage question when several cards are blocked at once.

Waiting · 4m

Waiting

peach · pulses slowly

Blocked on you — a permission prompt or a question. The only status that wants something. The pulse and the sidebar badge are both counting this.

The age matters: ten seconds and twenty minutes must not read the same, so the pill always says which.

Running

Running

blue · no elapsed time

Actively working. No age shown, because for a healthy session it isn't interesting.

Running · quiet 12m

Running · quiet

appears after a long silence

Still marked running, but nothing has been written for a while. Deliberately "quiet", not "stalled" — a long silent build is perfectly legitimate. You just want to know it's been twelve minutes either way.

Suppressed when the card owns a live workflow: those agents churn on a separate track that never touches the session's own timestamp, so the timer would fire on every healthy run.

Done · 3m

Done

teal · finished, not yet looked at

The turn ended. Teal is the "there's something here you haven't seen" colour, and it holds until you actually acknowledge it — no time-based decay, because clearing unseen finished work after a timer is exactly how you miss it.

Seen · 2h

Seen

grey · acknowledged

Done, and you've looked at it. The whole card dims: name, preview, and badges all step back so live work reads louder.

Done · 1h · live Done · 1h · ended

· live  /  · ended

terminal cards only

live — the process is still attached, so you can resume it where it sits. ended — the process is gone; picking this up means a cold start.

Absent means the registry can't say, and Serac won't guess. A missing annotation is genuinely "unknown", not "no".

8m…

Elapsed time alone

low confidence

Serac thinks the session is live but can't tell running from waiting well enough to claim it. Rather than assert the wrong one, it shows only how long it's been. An ellipsis means "I'm not sure".

Model pill

hue = cost tier · blue cheap → orange dear

Which model is answering, coloured by relative cost. The hue is a separate colour register from status — saturation and lightness are fixed, only hue moves, so a model pill never reads as a state.

Also the copy affordance: click it to copy the session's transcript path. A path is self-identifying when pasted into another Claude session, where a bare UUID gets mistaken for other kinds of id.

A trailing * means the model is inferred, not confirmed. An unrecognised family still gets its own stable colour rather than silently falling into one bucket.

✋manual </>edits 📋plan ⚡auto 🔀bypass

Permission mode

glyph + word, one colour per mode

How much the session asks before it acts. manual asks every time · edits accepts file edits · plan is read-only until you approve · auto decides for itself · bypass asks nothing at all.

Each mode has its own colour so the badge is never mistaken for a status signal — and bypass borrows the conflict red on purpose.

Worktree chip new

two letters + a tint · only when it isn't this checkout

Which worktree the session lives in. The letters come from the end of the folder name (fix-workflow-resume-liveness → RL), the tint from a hash of it.

Identity comes from the folder, never the branch. Branches get renamed and rebased away; if the chip followed the branch it would change colour under you. Hover for the full path.

No chip means the session is in the checkout you have open. Most cards carry none.

📡

Started from your phone new

replaces the letters on a bridge worktree

This session was spawned remotely, and lives in a throwaway worktree created just for it. It gets a fixed dish rather than initials because a monogram of a random id would be meaningless — two letters that look like identity but carry none.

Still going, quietly

blue outline · doesn't change the status

Three ways a finished-looking card isn't finished. 🐚 background shells still running · 💤 a scheduled wake-up, with the countdown · loop a session cron that will re-invoke it.

All three are tinted with the running colour on purpose: a done card that will start itself again in four minutes is idle, not finished.

3 shared files

Shared files

off by default · red outline

Another active session is editing the same files as this one — a merge conflict in the making. Hover for the list. Finished sessions are ignored, since their edits aren't a live conflict.

🤖3→ 🤖→

Agents

count = how many are live right now

Work happening underneath this session — workflow agents, subagents, or teammates, all collapsed into one chip rather than competing for the same row. Click to drill into the detail panel, which offers a switcher across them.

The chip is tinted by its own state, not the card's: live agents under an idle session still read as running. No number means none are live at the moment.

⚠→ ⛔→

Two windows, one session

rightmost · both clickable

⛔ Active in another window. Another VS Code window is driving this session. The card dims, but this chip deliberately stays full strength — it's the one useful thing on it. Click to switch to that window.

⚠ Live in two windows at once. Worse: two processes are able to append to the same conversation file. Click for a picker — keep it here, or release it. The card is not dimmed, because this window's claim is as real as the other's.

Actions

always last

📜 opens the transcript. × archives the card. On a live session the × reads "Archive" and is the escape hatch for a status that's got stuck.

Branch

its own row · hidden when there's no branch

The git branch. It gets a line to itself because it's the widest, most variable thing on a card — inline, it pushed the action buttons into wrapping.

Context bar

2px, across the card's bottom edge

How full the context window is, measured against the auto-compact threshold rather than the model's raw capacity — the threshold is what actually interrupts the session. Hover for both numbers.

It's chrome, not a chip: a hairline on the card's bottom border rather than a row in the body, so it costs no vertical space. Past 60% of the threshold it brightens (shown above at 35% and 78%).

Activity line

last row

What the session is doing. On a finished card it switches to what it finished with — the last thing it said, not the last tool it ran, because that's the useful line once work has stopped.

Spent new

A phone-started session whose process has ended. Its worktree was made for that one session and won't be reused, so nothing will ever resume this card — it recedes rather than competing with live work for your attention.

The top bar

Above the cards: what needs attention, and whether your phone can reach this workspace.

2 waiting 1 running 4 done 7 seen

Counts

One number per state, in the same colours the cards use. A state with nothing in it is omitted entirely rather than shown as a zero.

📡 📡

Remote Control new

far right · filled dot = serving

Whether a Remote Control server is serving this workspace — i.e. whether you can start a new session here from your phone right now. Filled teal dot and a bright dish when it is; hollow dot and a faded dish when it isn't.

The two states differ by the dot's fill as well as its colour, so it survives a colour-blind read. It's wordless by design — the top bar's job is the counts; hover for the explanation.

Worth knowing: sessions you started here are reachable from the phone either way. The server is only needed to start new ones.

Four rules the whole thing follows

Status colour is reserved

Peach, blue, teal, and grey mean waiting, running, done, and seen — nothing else is allowed to use them that way. Model hue and worktree tint are separate registers on purpose.

Shape carries the signal too

Filled pill, outlined chip, hollow dot. Nothing depends on colour alone, so the panel still reads without it.

Absence means unknown

A missing annotation is never "no". Serac shows what it can confirm and stays quiet about the rest rather than guessing.

The tooltip carries the words

Chips are small because sidebars are narrow. Every one of them has a hover that says it in full — the glyph is the index, not the whole entry.

Specimens are rendered with the recipes from media/panel.css, at the sizes the sidebar actually uses — small, because reading them in a narrow column is part of the job.
Colours shown are the dark-theme values; the light theme keeps the same meanings at adjusted contrast.
